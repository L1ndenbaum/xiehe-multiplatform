# iOS ATS Branch Policy

## 变更范围
- 为 iOS 增加按 Git 分支切换的 HTTP 明文策略。
- 默认策略为禁止明文 HTTP，仅在 `dev` 分支构建时开启。

## 涉及文件
- iosApp/iosApp/Info.plist
- iosApp/iosApp.xcodeproj/project.pbxproj

## 保留的业务逻辑
- 未修改任何 Compose/Kotlin 业务代码。
- 仅调整 iOS 打包时的 Info.plist 安全策略处理。

## 规则说明
- `Info.plist` 默认：`NSAppTransportSecurity -> NSAllowsArbitraryLoads = false`。
- Xcode 新增构建脚本 `Configure ATS By Branch`：
  - 分支为 `dev` 或 `refs/heads/dev`：设置 `NSAllowsArbitraryLoads = true`
  - 其他分支（含 `main`）：设置 `NSAllowsArbitraryLoads = false`
- 分支来源优先级：`GIT_BRANCH` > `CI_COMMIT_REF_NAME` > `GITHUB_REF_NAME` > 本地 `git rev-parse --abbrev-ref HEAD`

## 验证结果
- 通过静态检查确认脚本已注入 iOS target 构建阶段，并能写入最终构建产物的 Info.plist。
- 未在当前环境执行完整 iOS 编译链路验证。

## 风险点
- 若 CI 未提供分支环境变量，脚本会回退到 git 命令获取分支名；在浅克隆/无 git 元信息环境下可能拿不到分支名，默认会按非 dev 处理（即禁用 HTTP 明文）。
