# 缓存系统

## 模块
- 缓存仓储：`data/cache/ImageCacheRepository.kt`
- 二进制接口：`data/cache/ImageBinaryStore.kt`
- Android 持久化实现：`androidMain/data/cache/AndroidImageBinaryStore.kt`
- 业务接入点：`data/ImageFileRepository.kt`

## 功能分类
- 影像列表缓存
- 患者 ID -> 姓名映射缓存
- 影像二进制缓存（内存 + 持久化）
- 缓存命中优先下载策略

## 具体实现

### 1. 元数据缓存
- `ImageCacheRepository` 通过 `KeyValueStore` 持久化：
  - `image_cache.list.v1`：`List<ImageFileSummary>`
  - `image_cache.patient_name_map.v1`：`Map<String, String>`
- `mergeImageItems()` 支持增量覆盖更新。

### 2. 二进制缓存
- `ImageBinaryStore` 抽象：`read/write/delete`。
- `InMemoryImageBinaryStore`：跨平台默认内存实现。
- `AndroidImageBinaryStore`：写入 `filesDir/image_cache/image_<id>.bin`。

### 3. ImageFileRepository 中的双层缓存
- 内存 LRU（`LinkedHashMap` 语义）：最多 24 条。
- 持久层：`ImageCacheRepository`。
- 下载顺序：
  1. 内存命中返回
  2. 持久层命中返回并回填内存
  3. 网络下载并写入两层缓存

### 4. 并发控制
- `fileLocks` + `Mutex`：按 `fileId` 加锁，避免并发重复下载同一张图。

### 5. 失效策略
- 删除影像成功后调用：
  - `removeMemoryBytes(imageId)`
  - `cacheRepository.removeImage(imageId)`
  - `cacheRepository.removeImageItem(imageId)`
- 缩略图解码失败时会尝试 `evictImageCache(fileId)` 后重试一次。

### 6. 回退逻辑
- `loadImageFiles` 网络失败时：若本地有缓存且非 401，可回退返回缓存列表（`fromCache=true`）。
