# 会话与鉴权

## 模块
- 会话模型：`composeApp/src/commonMain/kotlin/com/xiehe/spine/core/store/SessionStore.kt`
- 鉴权仓储：`composeApp/src/commonMain/kotlin/com/xiehe/spine/data/AuthRepository.kt`
- 应用级调度：`composeApp/src/commonMain/kotlin/com/xiehe/spine/App.kt`

## 功能分类
- 登录/登出
- Token 刷新与过期前续期
- 会话恢复与补齐过期时间
- 401 自动重试
- 当前用户信息拉取与回填

## 具体实现

### 1. 登录链路
- `LoginViewModel.submit()` 调用 `AuthRepository.login()`。
- 登录成功保存 `UserSession` 到 `SessionStore`（Key: `user_session`）。
- `App.kt` 收到 `onLogin` 回调后进入主界面。

### 2. 会话恢复
- `AppContainer.create*()` 初始化 `AuthRepository`。
- `App.kt` 启动时调用 `authRepository.restoreSession()`。
- 若旧会话缺少 `accessTokenExpiresAtEpochSeconds`，仓储会尝试：
  1. 从 JWT `exp` 解码；
  2. 解码失败则兜底 `now + 300s`。

### 3. Token 刷新策略
- `AuthRepository.ensureFreshSession()`：当剩余有效期 <= 180s 触发刷新。
- `App.kt` 中 `LaunchedEffect` 长循环：
  - 每次按 `expiresAt - now - 120s` 计算等待时间（最少 30s）
  - 到点调用 `ensureFreshSession`
  - 刷新失败且 401 时强制登出并回到登录页

### 4. 401 自动重试
- 多仓储统一使用 `withRefresh(session) { ... }` 模式：
  - 第一次请求失败且 `isUnauthorized=true` 时先刷新 token
  - 刷新成功后自动重试原请求
  - 刷新失败则把失败结果上抛

### 5. 当前用户信息同步
- `App.kt` 登录后触发 `authRepository.getCurrentUser()`。
- `AuthRepository.profileToSession()` 将 profile 增量同步回 `UserSession`。
- `PersonalInfoViewModel` 在个人信息页加载/保存后也会回写 session。

### 6. 错误行为
- 认证失败（登录、刷新、拉 profile）均通过 `AppResult.Failure` 反馈。
- 若 `isUnauthorized=true` 且无法恢复，则统一执行：
  - 清空本地 session
  - 重置路由与 tab
  - 返回登录页
